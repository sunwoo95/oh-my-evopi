/subagents

서브에이전트 역할 프리셋

.evopi/agent/subagents/<name>.md 프론트매터로 이름·모델·명령 패턴 권한을 선언한다. 선언이 없으면 지금과 동일하게 즉석 호출로 동작 — 이 표는 opt-in 프리셋 목록이다.

역할modemodelfallbackeditbash 패턴
orchestrator primary claude-sonnet-5 — n/a task.researcher/coder/reviewer allow
coder subagent claude-sonnet-5 gpt-5-4 allow
npm * / git diff* / git log* * → ask
researcher subagent gemini-3-flash haiku-4-5 deny
git * / grep * / rg * * → ask
reviewer subagent claude-sonnet-5 — deny
git diff* / git log* / cat * * → deny
격차 근거 — evopi 현재는 approval.toolTiers[toolName](툴 이름 단위) + 전역 permissionGate.allow[] 하나뿐, 역할별로 다른 명령 정책을 표현할 자리가 없다(permission-gate.ts:618-641,739-747). reviewer 행의 * → deny 는 읽기전용 서브에이전트의 fallthrough 를 확인이 아니라 원천 차단하는 opencode 방식(agents/reviewer.md:8-13)을 evopi 스키마로 옮긴 것.

write-tier ask · permission-gate

승인 프롬프트 diff 미리보기 + "항상 허용"

지금은 원문 텍스트 + 이진(Yes/No)뿐이다(permission-gate.ts:851-854). 이미 있는 renderDiff(실행 결과 화면에서만 쓰던 것)를 승인 전에 재사용하고, 옵션을 하나 더 늘려 결정을 그 자리에서 영구화한다.

지금

edit_file(config/rate_limit.py)
> RATE_LIMIT_MAX = 100 → RATE_LIMIT_MAX = 1000 ...
(41자에서 truncate)

Allow this edit? [No] [Yes]

제안 4

diff 미리보기 ↓ (renderDiff 재사용)

Allow this edit? [No] [Yes] [★ Always allow]
config/rate_limit.py — write-tier ask
RATE_LIMIT_WINDOW_S = 60
RATE_LIMIT_MAX = 100
RATE_LIMIT_MAX = 1000
RATE_LIMIT_BACKOFF = "exponential"

❭ edit_file config/rate_limit.py — 위 diff 를 적용할까요?

No Yes Always allow this pattern
격차 근거 — evopi TUI 는 renderDiff(components/diff.ts:80)를 실행 결과 화면에는 이미 쓴다 (ipython-cell.ts:677-717, edit-summary.ts:6). 그런데 같은 렌더러가 승인 전 프롬프트 (permission-gate.ts:851-853)에는 안 쓰여 원문 텍스트만 truncate 해서 보인다. ctx.ui.select 의 시그니처(extensions/types.ts:116)는 options: string[] 뿐이라 "이번만"과 "항상"을 구분할 자리조차 없다 — 새 컴포넌트 없이 옵션 배열에 문자열 1개 추가로 해결 가능(비교 대상 툴 조사 불필요, evopi 자체 코드 내 능력-사용 불일치가 근거).
